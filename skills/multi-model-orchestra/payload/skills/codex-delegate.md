# 派给 Codex：任务书 → 独立 worktree → 后台派 → 读 diff、自己跑测试

## 1 值不值得派（先问这三个）
- 接口已经定死了吗？（没定死 → 你先把接口定了，或者自己做）
- 和页面无关、能独立成块吗？（要和页面来回对接口 → 自己做）
- 活大到比「写任务书＋读 diff＋复跑测试」的成本更大吗？（几十行 → 自己做）
三个都「是」才派。**修审查问题、小改动一律自己做。**

## 2 写任务书
Codex 只看得到任务和工作树，看不到你的对话。**写进去的每条事实先自己核实**——它太听话，你写错它就照着错的做。
```
## 目标
<一句话：要得到什么、怎么验证>

## 接口（已定死，不许改）
<签名/入参出参/错误语义；贴代码或「文件:行」>

## 验收标准（逐条可判定）
1. 命令 `…` 退出码为 0
2. <行为> …（含边界：空输入、并发、大数据量…）

## 要一起改的同类
- <列出所有同类位置，文件:行；让它改完用搜索确认没漏>

## 范围与禁区
- 可改：<路径>　不可改：<路径>

## 怎么自测
<命令与预期结果>

## 背景（只写必要的）
```
浏览器/网页任务另写清：目标页面与账号环境、允许的操作、**禁止的操作（付款、发消息、删除、提交表单）**、完成判据、遇到登录或验证码就停下汇报。

## 3 派（放后台，`run_in_background`）
```bash
git worktree add ../wt-<任务名> -b codex/<任务名>       # 给它单独的工作树，别和你同时改一份
bash .orchestra/bin/codex-worker ../wt-<任务名> - <<'TASK'
<任务书>
TASK
# 追加要求（同一个会话）：
bash .orchestra/bin/codex-worker --resume <会话ID> ../wt-<任务名> "追加：…"
# 浏览器/网页操控：加 --browser
```
边界（脚本固定的）：沙箱 workspace-write（只能写工作树）、无网络、不许提交；档位见 `.orchestra/orchestra.conf`。**装依赖、联网测试、提交推送由你做。**

## 4 交回后——这是你的活，不能省
1. 读它的终稿，但**以 diff 为准**：`git -C ../wt-<任务名> diff` ＋ 新文件（`??`）直接读。
2. **自己跑测试**，不信它说「通过」。对照任务书的验收标准逐条核，核不了的写成「未验证」。
3. 任务书里的事实有没有被它指出错误？有就先改任务书、追加。
4. 满意后你来装依赖、联网测试、提交；PR 里有 Codex 写的代码就是**混合来源**，交付**不带 `--agent`**，PR 描述里写明哪些部分由 Codex 写。
5. 汇报给用户：三句话——做了什么、验证了什么、有什么没验证。

## 退出码
`0` 成功 · `4` 前置条件不满足（比如拿主工作区当工作树，会被拒） · `5` Codex 失败/不可用（别悄悄换模型，告诉用户） · `6` Codex 违规提交了代码（先 `git log` 看一眼再决定保不保留）。

## T3 路径（没有 shell 脚本时；沙箱弱于脚本）
`bash .orchestra/bin/codex-worker --print-prompt . -` 取「工作约束＋脱敏后的任务书」，然后
`delegate_task({ role:"implementation", isolation:"worktree", mode:"async", target:{ providerInstanceId:"codex", model:"<CODEX_WORKER_MODEL>", options:{ reasoningEffort:"xhigh" } }, task:"<提示词>" })`
（`target` / `options` / `role` / `mode` 的写法已对真 T3 实测通过；`isolation:"worktree"` 要求当前仓库是 git，非 git 目录请用默认的 shared，并自己更小心地核对改动）；
追加用 `t3_thread_send` 发给该子线程。T3 的 `runtimeMode` 是审批粒度，**不等于**「只能写工作树、不联网、不提交」——这些要靠任务书里写明，并在交回后核对（`git log` 看有没有被提交过）。

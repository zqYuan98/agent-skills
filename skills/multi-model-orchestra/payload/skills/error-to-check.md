# 错误变成检查：别靠记性，靠机器拦

用户纠正一次、审查退回一条，就在修它的**同一个**合并请求里把这一类拦住。别只修这一处然后指望下次记得。

## 决策顺序（能往前就别往后）
1. **写成检查**（类型约束、lint 规则、守卫测试）——能机械判断的都走这条。报错信息写清**该怎么改**，不要只说「不对」。
2. **改结构**——能改接口或目录，让错的写法根本写不出来（比如把容易传错的两个同类型参数改成具名对象、把危险函数挪进只能被少数模块 import 的目录）。
3. **文字规则**——前两条都做不到才写进规则文档，并在提交说明或「处理：」里写明**为什么做不成检查**。

## 已有违规：记成欠账，只许减少
加检查时仓库里往往已有一堆违规。别为了过检查去改一大片，也别把检查放宽：
```bash
# 检查命令每行打印一条违规，写成【稳定 id】，如 路径:规则名:符号（别带行号，否则改一行就算新违规）
bash .orchestra/bin/ratchet init   <名字> -- '<检查命令>'    # 首次：把现有违规记成欠账基线（基线文件要提交）
bash .orchestra/bin/ratchet check  <名字> --strict -- '<检查命令>'   # CI/合并前：有新违规就失败；欠账还清了没收紧也失败
bash .orchestra/bin/ratchet update <名字> -- '<检查命令>'   # 还清一批后收紧基线；有新违规时拒绝
```
**新代码一处也不许有**；`update` 不能把新违规洗成欠账。
**检查命令的契约**：违规一行一条打到 **stdout**。**同一个 id 出现几次就算几条**——同一函数里同一规则违规两次是两条，基线和现状按次数比较，不会被去重吞掉。单个字符串形式的检查命令会以 `pipefail` 运行，管道末端的 `sort`/`head` 掩盖不了前面命令的错误。检查器自己坏了——退出码 ≥124、**退出码非 0 且 stderr 有内容**（哪怕它还输出了一部分结果，比如 `grep` 一个文件不存在、另一个文件照样有匹配）、或无输出且退出码 ≥2（`grep` 语法错是 2）——`ratchet` 会退出 4、不判定、不改基线，**不会**把坏掉的检查器当成「零违规」，也不会把残缺的输出当完整结果。要忽略 stderr 请显式写 `2>/dev/null`，由你负责。正常的是：退出 0（stderr 里有警告也行）；退出 1 且全无输出（`grep` 没匹配）；stderr 干净时有违规输出、退出码随意（`tsc` 用 2）。

## 文字规则要收敛
- 文字规则里有检查守着的，只留一句并写明是哪个检查。
- 检查已经完全守住的，**删掉**那段文字（规则文档越短越有人读）。

## 新仓库
第一个合并请求就带上**合并前自动跑**的类型检查和测试（再加上面的 `ratchet check --strict`，以及审查门 `bash install.sh --git-hook`）。CI 配置按你的平台写，至少这几步：类型检查 → 测试 → `ratchet check --strict`。

## 提交说明里怎么写
```
处理：<这一类错>
- 拦截方式：检查 / 结构 / 文字规则（三选一）
- 检查位置：<文件或命令>        （文字规则时改写：为什么做不成检查）
- 现有违规：<N> 条，已记入欠账 <基线文件>（只许减少）
```
